# Fidelity ledger

lattix never changes a lattice silently.  Every reader and every writer fills a
`FidelityReport` with one entry per element (plus a few lattice-level entries), each entry
carrying a class, a short upper-case code and a sentence that says what happened.  The
ledger is printed after every CLI conversion, can be saved as JSON, and is what the test
suite asserts on: an unexpected LOSSY or DROPPED code is a failing test, never a warning
that scrolls by.

## Classes

| Class | Meaning | Strict mode |
|---|---|---|
| `EXACT` | the target represents the element without any change (code `OK`) | passes |
| `EQUIVALENT` | a different model with the same reference-particle optics — a thick cavity written as drift + thin gap + drift, a field map written as the hard-edge element that preserves ∫B and ∫B², a thick kicker split around its centre, a diagnostic written as a marker | passes |
| `LOSSY` | the element is there but some information could not be represented: an aperture a drift cannot carry, a fringe integral the format lacks, a phase written for one species | fails unless allow-listed |
| `DROPPED` | the element has no representation in the target and was written as a comment, marker or drift of the same length | fails unless allow-listed |

## The report

`lattix.fidelity.FidelityEntry` has the fields `element`, `kind`, `cls`, `code`,
`message`, `details` (a free dict with the numbers behind the message) and `line` (source
line for reader entries).  `FidelityReport` carries `source_format`, `target_format`,
`source_file`, `target_file`, the `entries` and an `allowlist` of codes, and offers:

| Member | Purpose |
|---|---|
| `exact / equivalent / lossy / dropped / add` | record an entry (writers call these from their per-kind rules) |
| `counts` | `{"EXACT": n, "EQUIVALENT": n, "LOSSY": n, "DROPPED": n}` |
| `codes()` | non-exact codes with their multiplicity |
| `problems()` | LOSSY and DROPPED entries whose code is not allow-listed |
| `ok` | `True` when `problems()` is empty |
| `raise_if(strict)` | raise `TranslationError` on the first problem when `strict` is set |
| `summary()`, `print_summary()` | the one-line-per-code text the CLI prints |
| `to_json(path)` | machine-readable report (the `oracles` CI job uploads every `*.fidelity.json`) |

## Where entries come from

* **Readers** record parse-time downgrades: an unknown card, a field-map file that is
  missing, a species that had to be assumed, a default the engine would apply (elegant's
  500 MHz cavity), a root line that had to be guessed.  Strict readers raise on the first
  problem; permissive readers keep going and leave the entry in the ledger.
* **Writers** are table driven: each has a `RULES` table with one rule per IR kind, and
  `lattix.formats.base.check_rules_coverage` is a unit test for every writer, so a kind a
  writer cannot handle is a failing test rather than a skipped element.  Each rule records
  exactly one entry for its element; lattice-level entries (`element = None`) cover things
  such as an element definition outside the root line or a FLAME `source` that had to be
  prepended.
* **Gate tests** keep an explicit allow-list of the codes a given deck is expected to
  produce (see `tests/oracle/test_gate_phase2.py`), so a translation that starts losing
  something new fails even when the engines still agree.

## Command line

```
$ lattix convert in.dat --to madx out.madx            # ledger summary on stderr
$ lattix convert in.dat --to madx out.madx --strict   # exit 1 on the first LOSSY/DROPPED
$ lattix convert in.dat --to madx out.madx --report out.fidelity.json
$ lattix report in.dat --to elegant --json ledger.json   # ledger only, nothing kept
$ lattix inspect in.dat                                  # reader ledger + element counts
```
